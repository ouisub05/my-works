# 저장과 분류 — 이 폴더를 쓰는 법

## 1. 폴더 구조

```
에테르_세계관/
├── _저장과_분류.md          ← 이 문서
├── 1_설정집/                ← 원본. 여기만 고친다
│   ├── 00_인덱스.txt
│   ├── 01_세계_기초.txt
│   │   …
│   ├── 27_국가별_기입표.txt
│   ├── 98_용어사전.txt
│   ├── 99_변경이력.txt
│   └── 인수인계_HANDOFF.txt
├── 2_위키/                  ← 파생물. 고치지 않는다
│   ├── 에테르_위키.html         (단일 파일 · 읽기용 정본)
│   └── 마크다운/                (HTML에서 뽑은 것)
└── 3_보관/                  ← 날짜별 스냅숏
    ├── 2026-09-13_정합성세션/
    └── …
```

**핵심 원칙 셋**

1. **고치는 곳은 `1_설정집` 하나뿐.** 위키는 파생물이며 설정집에서 다시 뽑는다.
2. **`2_위키`를 손으로 고치지 않는다.** 고칠 일이 생기면 HTML을 고치고 마크다운을 다시 뽑는다.
3. **세션이 끝날 때마다 `3_보관`에 통째로 복사한다.** 폴더 이름은 `YYYY-MM-DD_세션이름`.

## 2. 설정집은 평면으로 둔다

`1_설정집`에 하위 폴더를 만들지 마십시오. 이유는 둘입니다.

- 번호가 이미 분류입니다. `00~06` 뼈대, `07~12c` 대륙, `13~15` 통합, `16~19` 판타지, `20~27` 제도, `98·99` 관리.
- 새 대화에 올릴 때 **드래그 한 번**으로 끝나야 합니다. 폴더가 갈리면 매번 헤맵니다.

## 3. 파일명 규칙

| 쓰지 말 것 | 이유 |
|---|---|
| `( )` 괄호 | 마크다운 링크가 `](` 다음 첫 `)`에서 끊긴다 |
| `※ — ·` | 도구마다 다르게 처리된다 |
| `:` 콜론 | 윈도·맥 파일명에 못 들어가 하이픈으로 변질된다 |
| 공백 | URL·스크립트에서 깨진다. `_`를 쓸 것 |

번호는 **두 자리 고정**(`01`, 09`)으로 두어야 정렬이 맞습니다.
쪼갤 때는 새 번호를 따지 말고 **접미 문자**를 쓰십시오 — `12`, `12b`, `12c`.
그래야 다른 파일의 기존 참조가 살아남습니다.

## 4. 새 대화에 올릴 때 — 이것이 제일 중요합니다

설정집 전체는 약 **1.5MB(18,800줄)** 입니다. 한꺼번에 올리면 대화가 금방 한계에 닿습니다.
**용건에 따라 나눠 올리십시오.**

### 기본 세트 (항상)
```
인수인계_HANDOFF.txt · 00_인덱스.txt · 98_용어사전.txt · 06_떡밥_미정사항.txt
```
약 220KB. 여기에 작업 규칙 `[0]`과 현황, 정본 규칙이 다 들어 있습니다.

### 용건별 추가

| 하려는 일 | 더 올릴 파일 |
|---|---|
| 힘·마법·등급 | 02 · 16 (+ 17 마물) |
| 종족·인구 | 03 · 15 |
| 종교·신성력 | 04 · 05 |
| 특정 대륙 | 07 / 09 / 10 / 11 / 12·12b·12c 중 **해당 것만** |
| 나라 제도·법·작위 | 21 · 26 · 27 |
| 살림·경제 | 20 · 20b · 22 |
| 전쟁·역병·이동 | 23 · 24 · 25 |
| 이름 짓기 | 08 |
| 플롯·사건 | 13 · 14 |

**대륙 파일은 전부 올리지 마십시오.** `07`(100KB)·`10`(88KB)·`11`(96KB)만 합쳐도 기본 세트를 넘습니다.

### 대화가 끝나면
바뀐 파일만 받아 `1_설정집`에 덮어쓰고, `99_변경이력`과 `HANDOFF`를 갱신하십시오.
**이 둘을 갱신하지 않으면 다음 세션이 무엇이 바뀌었는지 모릅니다.**

## 5. 보관과 되돌리기

가장 단순한 방법은 **날짜 폴더 복사**입니다. 세션이 끝날 때마다 `1_설정집`을 통째로
`3_보관/2026-09-13_정합성세션/` 같은 이름으로 복사해 두십시오.
석 달치만 남기고 지워도 충분합니다.

조금 더 하실 수 있다면 **Git**을 권합니다. 폴더에서 `git init` 한 번이면 됩니다.

```bash
git init
git add . && git commit -m "정합성 세션 — 별급 통일, 26 분할, 위키 재생성"
```

얻는 것이 큽니다.

- **무엇이 바뀌었는지 줄 단위로 보입니다.** 이번에 잡은 "정본을 선언하고 정본을 안 고침"
  같은 사고가 커밋 확인만으로 드러납니다.
- 되돌리기가 확실합니다. 날짜 폴더는 "어느 날 것이 맞더라"를 헷갈리게 합니다.
- 위키까지 넣지 마십시오. HTML 2.5MB는 한 글자만 바뀌어도 통째로 다시 저장됩니다.
  `.gitignore`에 `2_위키/`와 `3_보관/`을 넣으십시오.

## 6. 위키를 다시 뽑는 시점

설정집이 바뀌었는데 위키가 그대로면 **두 벌 관리**가 되살아납니다.
매번 뽑을 필요는 없고, 아래 셋 중 하나라도 해당하면 뽑으십시오.

- 값이 바뀌었다 (수치·이름·확정 사항)
- 파일이 갈라지거나 합쳐졌다
- 새 세력·인물·개념이 생겼다

순서는 **설정집 → HTML → 마크다운** 한 방향뿐입니다. 거꾸로 가지 마십시오.

## 7. 클라우드에 둘 때

- `1_설정집`은 **텍스트라 가볍고 동기화가 빠릅니다.** 클라우드에 두어도 됩니다.
- `2_위키`는 매번 통째로 바뀌므로 동기화 대상에서 빼는 편이 낫습니다.
- 다만 클라우드의 자동 버전 기록을 백업으로 믿지는 마십시오.
  **`3_보관` 또는 Git이 진짜 백업입니다.**
