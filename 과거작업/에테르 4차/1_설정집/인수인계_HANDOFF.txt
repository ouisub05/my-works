★ 사용자의 답을 대신 생성하지 말 것 ★

- ★규칙의 정확한 취지 (사용자 정정, 21~25 세션):
  이것은 ★질문을 하지 말라는 뜻이 아니다.
  ★질문을 던져 놓고, 사용자가 답하거나 위임을 선택할 시간도 없이
  ★같은 출력 안에서 어시스턴트가 임의로 답까지 내버린 것을 금하는 규칙이다.
  → ★질문은 얼마든지 해도 된다. ★답을 대신 쓰지만 말 것.
  → 과거에 이 조문을 지나치게 넓게 읽어 질문 자체를 주저한 사례가 있었음. 그럴 필요 없음.

- 질문을 던졌으면 거기서 멈추고 사용자 입력을 기다린다.
- 사용자가 아직 답하지 않은 항목에 "정리하면…" 식으로 답을 지어내지 말 것.
- 사용자가 확정한 내용만 파일에 기록한다. 확정 안 된 것은 [미정]으로 남긴다.
- 사용자 답이 "?" 또는 "." 등으로만 오면 = 답변 작성 중 유실된 것.
  답을 지어내지 말고 질문을 다시 정리해 보여주고 기다릴 것.
- 질문 여러 개를 한 번에 던졌는데 일부만 답이 오면, 빠진 질문을 다시 여쭐 것.

--- 확정 규칙 ---
1. ★발전 수준(추월/대등/약세)을 어시스턴트가 먼저 질문하는 것 금지.
   사용자가 자발적으로 지정한 것만 기록 (기존: 차쿠아=약세 / 인티마라=도로 기술 추월).
2. ★대륙 소속이 애매한 권역(중미·미세아·그라니타 등)은 소속을 정하지 않는다.
   · 부칙: 파일·표에서의 배치는 ★열람 편의일 뿐 소속 확정이 아님.
     본문·표에서 다룰 때 "소속 아님"을 명기할 것.
3. ★위임 창작: 사용자가 "위임/알아서"라고 하면 어시스턴트가 창작하되,
   반드시 ★"위임 창작분(변경 가능)"으로 명시해 보여주고 기록한다.
4. ★질문은 ★한 번에 한 문항씩. 여러 문항을 한 번에 내면 스크롤 시 위쪽이 가려져 답이 유실됨.
5. ★선택지 제시 방식 — ★본문 번호 방식 권장 (중요, 갱신됨)
   · ask 도구(버튼)는 이 프로젝트에서 ★한글 표기 깨짐이 반복적으로 발생함
     (수리아·마슈리크·21~25 세션 등. '방쥛간·곯·댓·섮임' 같은 글자 깨짐,
      심하면 ★질문 자체가 유실되어 JSON 문자열로 반환됨)
   · → ★본문에 1) 2) 3) 번호로 적는 방식이 안전하며, 최근 세션들은 그렇게 진행함
   · 깨진 표기가 그대로 고유명으로 확정되지 않도록 반드시 재확인할 것
6. ★사용자는 조합형 답을 자주 준다 ("1+2", "2+3", "3인데 단서는 …").
   → 선택지는 ★조합·단서 부기를 허용하는 문구로 낼 것.

--- 작업 습관 (★정합성 세션 ~ 역병 2-a 세션에서 굳은 것) ---
※ 이 절은 ★여러 세션에 흩어져 있던 교훈을 한자리에 모은 것 (근거는 99와 [8])
1. ★올릴 파일 = ★필수 다섯 + 과녁
   · 필수 = ★HANDOFF · 00 · 98 · ★08 · ★99 — ★어떤 세션에서도 뺄 수 없음
     (이름이 생기지 않는 세션도, 이력이 남지 않는 세션도 없음. 08을 빠뜨려 별지를 만든 전례 — 99)
   · 과녁 = 그 세션이 고칠 정본 파일 + 연쇄 대상. ★대륙 파일은 필요한 것만
   · ★전부 올리면 대화가 금방 한계에 닿음 (설정집 전체 약 1.5MB)
2. ★값은 정본 한 곳에만 (★00 [정본 규칙]이 어디인지 정함)
   · 다른 파일에는 ★포인터만 ("★연도는 24-VI-2가 정본. ★여기에 적지 말 것")
   · 파일 말미의 ★[연쇄 반영] 블록은 ★이력이지 값이 아님 ([8]-7)
   · 사본을 둘 수밖에 없으면 ★소유권을 명기 (값은 어디, 해설은 어디 — 27 방식. [8]-8)
3. ★큰 작업은 ★세션 안내문을 먼저 지음
   · 담을 것 = 범위(할 것·★하지 않을 것) / 올릴 파일 / 재료 / ★제약 / 문항 순서 / 점검표
   · 보관 = ★.github/세션안내/NN_이름.md — ★지우지 말 것
     (제약 목록이 곧 설정 요약이며, "하지 않을 것"이 범위를 자른 근거로 남음)
4. ★세션 끝 점검 — 이 다섯을 빠뜨리면 미반영
   ① ★99 맨 위에 블록 (무엇을 / 왜 / 어느 파일을)
   ② ★HANDOFF [5]를 ★현재 시점 기준으로 다시 씀 + ★[7]에 5~10줄 ([8]-12)
   ③ ★고친 파일마다 ★[상태] 헤더도 함께 고침 ([8]-10)
   ④ ★06 [미정]에 해소 표시 / 새 [미정]은 번호를 이어 붙임
   ⑤ ★"현행 N건"처럼 숫자를 박은 줄이 있으면 ★전부 되짚음 (계보 6→7건 전례 — 99)
5. ★보류 중인 값에 기대 쓴 문장에는 ★[보류] 표시 — 보류를 푸는 세션은 ★그 문장들을 전부 되짚음 ([8]-9)
6. ★현황을 단정하기 전에 ★실제 파일을 열어 볼 것 ([8]-2 · 06-18 전례)

--- 진행·출력 규칙 ---
- 설정 논의는 지구 지명으로 하되, 파일에는 확정된 가상 이름을 씀
  (좌: 확정명 / 우 괄호: 지구 대응. 색인은 08_작명_대조표).
- 진행 방식: 나라(문명) 하나를 깊게 → 대륙 관계도 → 작명 → 다음.
- ★문명 설계 표준 항목 (8항목):
  정치 / 종족 구성 / 인구 규모 / 경제 / 신앙 + 가호 형태 / 종족 역할 / 대외 관계 / 대외 인지
  (발전 수준은 묻지 않음)
  · 인구 규모 = 대략 수치 기입 방식. 원칙은 01, 세력별 수치 정본은 15
- ★21~25 세션 신설 → ★26 세션에서 ★세 줄로 확장: 각 나라 항목에 아래를 기입할 것
  · ★법의 꼭대기 = 국가법 / 종교법 / ★관습법 / ★연맹 규약  (26-XI-1·XIII-4 신설)
    - ★종교법은 다시 셋: ★교단 우위형 / ★신 바로 아래형 / ★셈이 꼭대기형 (26-XII-1·XIII-1)
  · ★조문에 종족이 적혀 있는가 = 예 / 아니오  (그 나라의 성정을 드러냄)
  · ★조문에 성별이 적혀 있는가 = 예 / 아니오  (그 나라가 무엇을 자연이라 우기는지) [26 신설]
  · ★함께 기입: ★세습 형태 (장자 / 아들만 / 딸만 / 둘 다 — 26-IV-2)
- ★파일 수정 후에는 present_files로 사용자에게 보여준다.
- ★인물 설계: 인물 1명(주변 인물 포함)이 끝날 때마다 즉시 파일에 기록하고
  ★수정된 파일만 첨부해 출력한다. 전체 zip 병행 금지. 누락 금지.
